## Current implementation

### Drawer and favourites

`DrawerPanel.kt` owns a native ListView with search, long-hold app information, explicit Favourites mode, and a miniature Home arrangement. Tapping apps in Favourites mode adds/removes them immediately. Miniature icons support drag/drop; remote Select offers move earlier/later. Overflow favourites can be reordered into visible slots. Original favourites were restored after testing: Grayjay, Cloudstream, Animiru.

The alphabet rail spans the full screen height, separate from the content column. It shows #,0-9,A-Z; unavailable groups are dimmed. Touch scrubs directly to a section. Remote Right enters the rail, Up/Down skip empty groups, Left/Select returns to the app list. A readable letter/count appears in the hint. The highlight follows scrolling/selection. Section starts/counts are cached once per search change, with accent normalization and deterministic group ordering. The full-height rail prevents tiny labels when the favourites preview opens. MainActivity's drawer swipe area is restricted to the toolbar, not the entire content column.

Settings access is again a full bottom row. Settings search and categories remain. A prior Down-from-search focus trap was corrected.

### Centre preview and resume

`RemoteActionService.kt` identifies eligible player/reader windows and updates `LauncherState.lastApp` when Follow last media app is on (default). `PreviewCaptureService.kt` uses user-approved MediaProjection, crops eligible bounds and atomically stores one local frame per mode. Cloudstream/Animiru controls are filtered to avoid saving menus or player chrome. Surface renewal plus a600ms eligibility check handles static/paused content. Capture is optional and may need renewed Android consent after install/restart. Protected video may remain black.

`ExternalPreview.kt` renders the captured picture, supports Fit/Crop/Stretch, and always displays previous/play/next icons. Unsupported session commands are disabled. Play opens the app-owned session intent when available, otherwise its launcher activity; a valid paused Watch session advertising Play receives that command. Capture-paused status refreshes every1.5s while Home is attached. No other app is actually embedded or suspended by this launcher.

**Animiru finding:** installed package `xyz.Quickdev.Animiru.mi`; player `eu.kanade.tachiyomi.ui.player.PlayerActivity` is non-exported/singleTask. Device logs showed it finishing with `app-request`; the remaining task held only MainActivity and no media session. Generic launcher APIs cannot reopen that private player at the episode once it closes. Do not present an instant closed-player restore as fixed. Keep app-owned intents/warm tasks; investigate an official deep link or supported integration separately.

`WatchPlayer.kt` can stage the next LOCAL file after the completion threshold when leaving/screen-off, showing Preparing then Next ready after the first frame renders. External next-episode loading remains app-dependent; no universal next-episode preload is implemented.

### Remote and macros

`RemoteControls.kt` saves mappings per Android device descriptor and key. Home/Power/Unknown remain reserved raw keys; another delivered key can map to Screen off. Learning accepts a Back release even if its down is absent, and runtime matching now handles that case too. Learning times out after30seconds without saving, preventing remote-only cancellation traps. Navigation, Screen off and Record/stop remain usable while editing.

`RemoteActionService` intercepts mapped key events globally when accessibility is enabled. Home explicitly opens Snapplication, independent of Android's default launcher. Screen off uses Android's lock-screen accessibility action on API28+. It does not promise physical wake, shutdown, TV power or independent Huawei desktop output power.

Macro version2 supports up to20 actions across allowed apps: exposed clicks, app transitions and delivered/mapped navigation. `Record/stop macro` is itself remappable. A floating Stop control saves; new named recording starts from Home; quick recording within the launcher normalizes Home first. Per-step packages and bounded foreground waits support replay across apps. Legacy macros remain readable. Optional replay confirmation is preserved (enabled on this phone). Private/password fields, editable text and protected system permission/settings surfaces are excluded. Scroll gestures and arbitrary raw touch paths are NOT recorded. Thus this is cross-app action recording, not unrestricted gesture recording.

Selectors prefer ID plus class or exposed labels/ancestors. Missing/ambiguous targets stop playback. Stable IDs/classes do not guarantee semantic identity if an app reuses a control for another action; this needs further hardening. Do not capture post-click toggle text as a precondition: Start may already read Pause when the accessibility event arrives. Accessibility `onInterrupt` must not cancel macros; Huawei Clock invokes it during normal tab changes.

### Setup and icon

`SetupGuide.kt` presents seven skippable pages: Home, favourites, accessibility, screen capture, optional media access, remote/macros and default Home. Permission status refreshes after returning from Android. Screen capture remains Android-approved; no permission bypass. Setup is reachable again from Settings.

The icon is thin angular linework depicting crossed thumb/index finger. `AppIconTheme.kt` switches BlueIcon/GoldIcon aliases (blue/white or gold/black) without disabling the MainActivity HOME component. Main/TV manifests preserve launcher/Leanback discovery. Both theme switches were verified and blue restored. Some launchers cache icons. The CEC message was removed.
