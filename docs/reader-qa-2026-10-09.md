# Reader verification — 9 October 2026

Baseline: eaecf69. Device: Meebook M6, Android 11. Mate 10 Pro was not touched.

## Verified on the physical reader

- Read PDF in internal storage: automatic page capture; Home → Continue returns to the same book/page, before and after a page turn. Screen-content comparison was identical on resume.
- Read EPUB on removable SD storage: same-page resume at pages 40 and 41/139. Root cause was a primary-storage-only resume URI. The verified vendor content-URI resolver now receives its own saved book path through a private, read-only metadata provider with a temporary grant. No book file is served or new storage access granted.
- Read downloaded CBZ: same-book/page resume before and after a page turn; identical screen content on resume.
- Read unchanged PDF page: saved JPEG timestamp and size unchanged across 16 seconds. Opening its controls for seven seconds did not replace the page.
- Android reports no MediaProjection session. Read takes occasional still screenshots; no virtual display or continuous recording is started.
- Mihon: same chapter/page resumed at pages 1 and 3/25. The saved page-3 thumbnail matched the current page (mean channel difference 5.28/255 after resizing/JPEG encoding). Switching from Read to Mihon changed the resume target correctly.

## Boundaries

Read's silent canvas is sampled every five seconds, so leaving immediately after a page turn can retain the prior preview. Other readers use accessibility events. Protected pages and readers without recognised page surfaces may not supply a preview. No battery-life or temperature improvement has been measured. Unknown Meebook Read versions use normal app launching rather than an unverified vendor protocol.

All-edition build/lint/unit checks passed before the final portrait sizing adjustment (16 tests per edition, 48 total). Final verification will be recorded after that adjustment. No public release.
